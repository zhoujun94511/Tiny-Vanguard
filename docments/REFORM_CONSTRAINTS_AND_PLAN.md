# Tiny Vanguard 玩法、节奏与内容架构设计规范与约束

> 本文档在代码改造前确立改造基准、内容配额与工程红线，所有后续扩展必须严格遵守以下约束，防止系统耦合退化或单文件构建超限。

---

## 一、 核心改造原则（What to Do / What NOT to Do）

### ✅ 必须遵守（DO）
1. **公共基建零侵入复用**：
   - `GameRuntime`、`GameClock`、`GameStateMachine`、`ObjectPool`、`SpatialGrid`、`SceneArena`、`EntityRenderer` 作为公共引擎底座保持稳定。
   - 新增关卡（如熔岩峡谷、霜雪栈桥）**只通过新增 `LevelDefinition`、`EnemyDefinition`、`PropTheme` 参数与内容池配置完成**，严禁在核心系统里写 `if (level.id === 'ember-canyon')` 等关卡硬编码分支。
2. **四个内容维度的量化基准（每项 ≥ 20 个真实生效条目）**：
   - **减益/异常状态 (`DebuffDefinition`) ≥ 20 种**：全部挂载在 `EnemyEntity` 的定长状态位/计时器上，在 `StatusEffectSystem` 中产生真实数值或控制效果（减速、冻结、灼烧、中毒、破甲、感电、眩晕、流血、瘟疫传染、斩杀印记等）。
   - **增益效果 (`BuffDefinition`) ≥ 20 种**：可供木桥双路光门、连杀里程碑、临时/永久强化统一调用。
   - **装备/遗物 (`EquipmentDefinition`) ≥ 20 种**：独立于核心战技的可穿戴战利品/被动装备，荒野生存可通过升级或精英掉落获得，通道守卫通过击杀直接穿戴到主角身上。
   - **技能/升级 (`UpgradeDefinition`) ≥ 20 种**：覆盖 5 种自动战技解锁与共鸣进化、主动技（`Space` 冲刺 / `E` 圣盾 / `Q` 星爆）强化、元素附魔与属性成长。
3. **“前期猥琐发育 → 后期割草爽感”节奏曲线**：
   - **发育期（0%～25% 流程）**：低并发、低移速、低血量，确保玩家快速拿到第 1～2 次升级或第 1 件装备，走位安全容错高。
   - **对抗期（25%～65% 流程）**：引入冲锋怪、远程法师与精英，考验走位躲避预警并完成多武器+装备联动成型。
   - **割草高潮期（65%～100% 首领前）**：大幅缩短刷怪间隔并提高批次数量，同时混入大量低血量集群杂兵（Swarm Fodder），让成型的多重弹丸、连锁闪电、环绕星盾与冰霜冲击产生**连续大面积清屏、暴击飘字与怒气暴涨**的割草快感。
   - **终局首领战**：暂停普通杂兵膨胀，刷出对应关卡专属首领与受控增援，击败后正式结算胜利。
4. **热循环零 GC 与池容量守恒**：
   - 严禁在 `update*`/`step*`/`sync*`/`draw*` 热路径中 `new THREE.Vector3`、`.clone()`、`Object.keys()` 或动态创建状态数组。
   - `EnemyEntity` 的异常状态必须使用定长 `Float32Array`（按索引对应 20 种 Debuff 剩余时间）存储，零对象分配。

### ❌ 严格禁止（DO NOT）
1. **禁止写“假数据”或空壳文本**：每个 Buff、Debuff、装备与技能 ID 都必须在战斗/属性计算中产生可测量的真实效果，禁止只改显示名称而不接通规则。
2. **禁止在场景与渲染器中硬编码特定关卡 ID**：地形色板、跨线材质、障碍与通道样式必须由 `LevelDefinition` 中的主题字段驱动。
3. **禁止打破双模式差异化交互与首领机制隔离**：
   - 草甸/峡谷等**生存模式**：保留自由移动、全向视角跟随与三选一升级弹窗；首领按玩家战力动态缩放血量，保留 `0.55x` 移速下限、`1.45x` 易伤上限、单次 `8%` 爆发上限与 50% 血二阶段护盾狂暴（可风筝应对冲锋与砸地）。
   - 木桥/栈桥等**通道守卫模式**：保持锁定视角、防线区限位与打怪/光门直接增益；狭路不可风筝，首领**严禁高速冲锋与全桥砸地**，采用 `0.68x` 攻城推进、`0.38x` 减速下限、可躲避前向扇形弹幕与二阶段略微后退，触碰红线仅重创（`45%` 最大生命）并击退，禁止满血秒杀。
4. **禁止将所有关卡平铺塞满主界面，必须规范分组与复用分页组件**：
   - 主界面（`MainMenu`）**永远只保留「荒野生存」与「通道守卫」两大类玩法入口卡**。
   - 各自玩法下的关卡均通过 `modeGroup` + `stageOrder`（第 1、2、3... 关）配置在子界面中按顺序展示，默认全部开放（带已通关/当前推进状态），并在单关胜利结算页提供「下一关」顺次推进。
   - **标准化分页红线**：关卡或图鉴等列表界面禁止无限向下无限堆叠，**桌面端默认单页上限 `4` 条，移动端（`<= 640px`）默认单页上限 `3` 条**；超出上限自动切分页并**自动定位到当前推进关卡所在页**。所有分页需求必须统一复用公共逻辑 `usePagination.ts` 与公共组件 `PaginationBar.vue`，不得在各页面重复手写切片与页码计算。
5. **禁止破坏离线单 HTML 门禁**：严禁引入外链图标、字体、纹理或超过 `1.5 MiB` 单文件体积红线；继续保持 `npm run gate` 全链路通过。

## 三、 门禁验证标准（自动化检查）
1. `prebuild-check.mjs` 校验：0 循环依赖、安全红线、热循环零 GC，且校验 `BUFF_DEFS.length >= 20`、`DEBUFF_DEFS.length >= 20`、`EQUIPMENT_DEFS.length >= 20`、`UPGRADES.length >= 20`。
2. `ConfigValidator.ts` 校验所有 4 个正式关卡（及测试关卡）配置完整且引用合法。
3. `vitest` 测试覆盖：20 种 Debuff 执行、22 种 Buff 应用、20 种装备穿戴叠加、5 大战技联动、割草波次与 `xpCurve` 曲线、光栅线段扫掠防穿透、双模式 BOSS 平衡与 4 关卡配置加载（共 38 项测试）。
4. `npm run gate` 含单文件体积与离线纯净度检查全绿，并通过 Chrome 实机截图验收。
